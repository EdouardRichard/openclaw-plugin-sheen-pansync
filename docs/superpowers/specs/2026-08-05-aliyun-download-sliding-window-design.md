# 阿里云盘下载 2 次/60 秒严格滑动窗口设计

**日期：** 2026-08-05

**状态：** 已复核

## 1. 背景与根因

上一版已经把同一 OpenClaw 运行时内的下载生命周期改为单通道 FIFO 串行，并为阿里云盘 OpenAPI 请求增加了全局 350 ms 节拍以及 `getDownloadUrl` 的 10 次/10 秒端点窗口。

真实使用仍表现为前两个小文件下载成功、第三个下载失败。串行门禁只限制同时存在的下载数量；当前一个小文件完成后，下一个下载会立即开始，因此三次完整下载仍可能在 60 秒内启动。现有 OpenAPI 节拍限制也没有为一次完整下载动作提供 2 次/60 秒的启动窗口。

本设计采用社区资料和真实失败模式支持的保守兼容规则：非分段下载在任意滚动 60 秒窗口内最多启动两次。该阈值不是插件能够确认的阿里云盘官方公开契约，文档不得将其描述为官方保证。

## 2. 部署与保证边界

目标部署是一台主机上的一个 OpenClaw。该 OpenClaw 可以同时承载任意数量的会话、Agent 和 `pan_sync_download` Tool 调用。

插件必须保证：

- 同一插件数据目录下，所有会话和 Gateway 进程共享同一个下载启动窗口。
- 任意滚动 60 秒窗口内，最多预占两个完整下载启动名额。
- OpenClaw 或插件进程重启后，尚未过期的名额继续生效。
- 单个下载继续使用一个非分段、非 Range 的内容 GET。
- 不增加 Redis、外部协调服务或第三方 SQLite npm 包。

本设计不保证多台主机、不共享插件数据目录的多个容器或多个公网出口之间的分布式限流。未来若扩大为多主机部署，需要单独设计集中式协调，不能默认沿用本地 SQLite 保证。

## 3. 方案选择

曾考虑以下三种方案：

1. 仅使用进程内滑动窗口。实现简单，但不能覆盖 Gateway 多进程或进程重启。
2. 使用 Node.js 内置 `node:sqlite` 持久化滑动窗口。可以覆盖本次单主机范围，不增加运行时 npm 依赖。
3. 使用 Redis 等集中式服务。可以覆盖多主机，但会增加部署、凭据、可用性和运维负担，超出本次范围。

采用方案 2。

## 4. 组件边界

### 4.1 下载生命周期门禁

保留现有容量为一的 FIFO 下载门禁。它覆盖一次 `pan_sync_download` 的完整生命周期，确保同一 OpenClaw 运行时内不会并行打开多个远端下载流。

门禁负责并发，不负责 60 秒频率窗口。

### 4.2 持久化下载启动协调器

新增独立的阿里云盘下载启动协调器。它负责在真正开始一次完整下载前原子预占启动名额。

协调器使用 Node.js 内置 `node:sqlite`，数据库文件固定为插件私有数据目录下的：

`pan-sync-helper/locks/download-rate-limit.sqlite`

该文件必须与现有 Token 租约数据库 `lease.sqlite` 分离，避免下载等待与凭据刷新互相争抢数据库事务。

协调器不得访问 OpenClaw 或其他插件的数据库，也不得依赖 OpenClaw 的内部 SQLite 表、`sqlite-vec` 传递依赖或未公开 API。

### 4.3 Worker 边界

SQLite 操作在插件拥有的 Worker 中执行，避免同步数据库操作阻塞 Gateway 主事件循环。每次数据库事务必须保持短小；计时等待在事务提交后进行，绝不能持锁等待。

## 5. 滑动窗口算法

窗口限制为两次启动、60,000 ms，并在释放边界增加 250 ms 本地安全余量，避免计时器精度和进程调度抖动导致边界请求过早发出。每次申请按以下步骤执行：

1. 打开独立限流数据库并开始 `BEGIN IMMEDIATE` 短事务。
2. 只有在成功取得事务锁后才读取一次新的系统时间；该事务时间用于删除、等待计算和新记录插入，不能使用等待锁之前的调用时间。
3. 删除所有已经到达过期边界的启动记录，并检查是否存在晚于事务时间的记录。
4. 没有时钟回拨且当前少于两条记录时，插入事务时间并提交。本次申请获得名额。
5. 已有两条记录时，读取最早记录的过期时间并提交事务，不插入记录。
6. 在不持有数据库锁的状态下等待至窗口开放，然后重新从步骤 1 原子竞争。

并发申请不能根据事务外读取的数量直接放行。只有成功提交启动记录的申请才算获得名额。

记录必须在请求阿里云盘 `getDownloadUrl` 之前写入。获得名额后应立即请求下载地址并紧接着发起内容 GET，避免先取得签名 URL、长时间等待后再使用可能过期的地址。

已经提交的名额不因以下情况提前退还：

- `getDownloadUrl` 失败；
- 内容 GET 失败；
- 内容流中途失败；
- 用户取消；
- Gateway 或 Worker 崩溃；
- 文件落盘或字节数校验失败。

这是有意的保守策略：宁可在 60 秒内少发起一次下载，也不能因为失败或崩溃补发第三次。

## 6. 下载数据流

一次下载按以下顺序执行：

1. 获取现有 FIFO 下载门禁。
2. 获取凭据并解析资源盘上下文和目标文件元数据。
3. 执行大文件确认检查和本地目标安全检查。
4. 如果需要大文件确认，立即返回 `DOWNLOAD_CONFIRMATION_REQUIRED`；该调用没有申请下载启动名额。
5. 在 Provider 准备调用 `getDownloadUrl` 前申请持久化启动名额。
6. 如窗口已满，在插件内部等待，不访问阿里云盘。
7. 获得名额后调用 `getDownloadUrl`。
8. 立即发起一个不带 Range 的内容 GET，并把响应流写入安全的工作区目标。
9. 完成字节数校验、文件关闭、失败清理和稳定错误映射。
10. 在 `finally` 中释放下载生命周期门禁。

本次设计不增加分片下载、并行内容请求、断点续传、自动重试或下载 URL 刷新循环。

## 7. 等待交互

窗口已满时，当前 Tool 调用在插件内部继续等待并保持执行中。插件获得名额后自动继续同一次下载。

不得把普通窗口等待作为 Tool 终态返回，也不得要求 AI 根据一个瞬时 `retryAfterSeconds` 自动再次调用。这样可以避免重复调用、竞争放大和多会话下不可靠的预计时间。

`skills/pan-sync-upload/SKILL.md` 必须明确要求 AI：

- `pan_sync_download` 可能因共享的 2 次/60 秒窗口而等待；
- Tool 仍在执行时不得重复或并行发起替代下载；
- 插件会在获得名额后自动继续，不需要 AI 手动重试；
- 只有 Tool 返回最终稳定错误后才向用户报告，不得自动循环重试。

`pan_sync_download` 的 Tool description 应包含简短的内部排队和禁止重复调用说明。README 应面向用户解释：连续下载的第三个及后续文件可能明显等待，这是限流保护，不代表 Tool 已挂死。

当前插件注册接口没有经过确认的 Tool 进度回调，因此本版不依赖未公开能力发送实时等待消息。如果未来 OpenClaw 提供稳定的正式进度 API，可以单独增加非终态提示，例如“等待下载窗口，预计约 N 秒后继续”，但该提示不能结束当前 Tool 调用，也不能指示 AI 重试。

## 8. 错误、取消与故障关闭

- 等待下载生命周期门禁或滑动窗口期间取消时，停止该调用，不访问阿里云盘，也不影响其他等待者。
- 已经提交启动记录后取消时，记录保留至窗口自然过期。
- SQLite 文件不可创建、数据库不可打开、事务无法在有界时间内完成、Worker 协议异常或数据库状态无法可信读取时，必须故障关闭：拒绝启动下载，不能绕过窗口。
- 内部数据库路径、SQL、Worker 错误、Token、签名 URL、drive ID、file ID、绝对路径和原始响应不得出现在 Tool 结果中。
- 本次设计不把本地协调等待伪装成服务端 `RATE_LIMITED`。协调器故障统一映射为现有 `DOWNLOAD_FAILED`，不新增公开错误码，也不暴露内部故障细节。

## 9. 时钟与窗口边界

持久化协调需要使用可跨进程和重启比较的系统时间。事务时间必须在 `BEGIN IMMEDIATE` 成功后获取，避免最多 30 秒的锁等待被错误计入新记录的年龄。测试必须覆盖真实锁等待、60 秒加 250 ms 安全余量的释放边界和系统时间回拨的保守行为。

定义固定的 `CLOCK_ROLLBACK_TOLERANCE_MS = 5,000`。若最新记录比锁后事务时间最多晚 5,000 ms，保留该 future row、不插入新记录，并返回一次完整但有界的 60,250 ms 保守等待；这保证等待不会超过协调器上限。若 future skew 超过 5,000 ms，则视为主机时钟异常并回滚、故障关闭为 `DOWNLOAD_FAILED`，不得删除、绕过记录或无限等待。系统时间大幅跳变属于主机时钟管理问题，本版不引入外部时间服务。

## 10. 测试设计

实现必须先添加失败测试，再修改生产代码。至少覆盖：

1. 前两个申请可以提交启动记录，第三个在最早记录满 60 秒并经过 250 ms 安全余量前不能获得名额。
2. 精确释放边界只放行一个合格等待者，并继续保持总量不超过两次。
3. 多个并发申请通过 SQLite 原子事务竞争，不会同时越过第二个名额。
4. 两个独立 Node 子进程共享同一数据库时，总启动数仍不超过两次。
5. 关闭并重新创建运行时后，未过期记录继续阻止第三次启动。
6. 等待期间取消不会插入记录、访问远端或阻塞后续合格申请。
7. 获得名额后失败或崩溃模拟不会提前返还记录。
8. SQLite/Worker 不可用时故障关闭，不调用 `getDownloadUrl` 或内容 GET。
9. 大文件确认返回不消耗启动名额。
10. 下载仍使用单个不带 Range 的内容 GET，且不存在自动网络重试。
11. 多会话风格的并发 Tool 调用由生命周期门禁和持久化窗口共同约束。
12. Tool、Skill、README 和打包产物包含一致的等待说明，且不指示 AI 自动重试。
13. 现有 Token 刷新 SQLite 租约测试继续通过，证明独立数据库没有造成回归。
14. 泄漏测试证明数据库路径、内部等待状态和远端敏感信息不会进入公开结果。
15. 小幅时钟回拨采取保守等待，大幅时钟异常故障关闭且不会无限等待。
16. Worker 在真实 SQLite 锁等待并释放后写入的时间来自锁后系统时间，而不是申请调用前时间。

完成聚焦测试后运行完整的 `npm run verify`，并检查打包后的精确产物，而不是只验证源码导入。

## 11. 真实验收边界

用户已授权在本机现有 OpenClaw 部署上自主执行本设计所需的真实测试验收。该授权只在实现和自动化验证通过后生效，并且只覆盖本节定义的有界下载旅程；不包含远端删除、发布、推送、创建 PR、修改账号配置或限流压测。

验收使用三个已选定的非敏感小文件，按顺序调用下载。如果当前环境没有保留可安全复用的三个明确文件标识，允许先执行一次有界 `pan_sync_list` 来选择三个普通小文件；不得循环搜索、遍历整个资源盘或追加无关探测：

- 前两次下载按正常串行路径执行；
- 第三次调用保持运行并等待窗口开放；
- 第三次在合格时间点自动继续，不由 AI 重复调用；
- 三次均返回 `downloaded`，本地字节数与预期一致；
- 全程不触发 429 压测、不循环重试、不删除远端文件。

可以安装本次构建出的精确本地包、让本机在线 Gateway 加载该包，并在新会话中验证 Tool 注册和实际可用性。验收必须复用同一个经过自动化检查的精确包产物；不得把源码测试通过替代为已安装包验证，也不得把 Gateway 健康替代为真实下载成功。

报告只保留调用数量、等待是否发生、是否自动继续、稳定状态和字节数是否一致，不包含文件名、路径、file ID、drive ID、签名 URL、账号信息或原始日志。

## 12. 非目标

- 不支持跨主机或不共享数据目录的分布式限流。
- 不引入 Redis、第三方 SQLite 包或 OpenClaw 内部数据库依赖。
- 不新增目录下载、批量下载 Tool 或后台下载任务系统。
- 不实现下载进度推送、Range 分片、断点续传或自动重试。
- 不修改 Refresh Token 获取方式、资源盘唯一目标规则或上传分片契约。
- 不提交、推送、发布或创建 PR，除非用户另行明确授权。

## 13. 成功标准

在单主机单 OpenClaw 部署范围内，不论会话和并发 Tool 调用数量如何：

- 任意滚动 60 秒窗口内最多提交两个完整下载启动记录；
- 未获得记录的调用不能访问 `getDownloadUrl` 或内容下载地址；
- 第三次及后续调用在插件内部等待并自动继续，不要求 AI 重试；
- 重启、失败和取消不能导致名额被提前返还；
- 其他插件、OpenClaw 数据库和现有 Token 租约数据库不受该限流数据库锁影响；
- 自动化验证和经授权的真实账号验收分别通过。
- 本机真实验收复用经过验证的精确包产物，并证明第三次调用由插件内部等待后自动继续。
