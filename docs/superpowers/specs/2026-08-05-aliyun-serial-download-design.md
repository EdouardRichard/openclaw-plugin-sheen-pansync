# 阿里云盘完整生命周期串行传输设计

**日期：** 2026-08-05

**状态：** 用户已批准方案，待书面复核

## 背景与判断

真实 OpenClaw 验收中，五个文件按 3+2 批次下载时，前三个稳定成功，后两个稳定返回 `DOWNLOAD_FAILED`。第二批虽然在前三个客户端流完成约 1.5 秒后才启动，但阿里云服务端可能仍在下载并发时间窗内保留前三个占用。

此前增加的 350 ms OpenAPI 请求节拍已确认安装生效，但未改变 3 成功、2 失败的结果。因此下一步不继续猜测服务端窗口长度，也不增加固定冷却或重试；直接把同一 Gateway 内的整个下载生命周期改为严格串行。

当前单次 `pan_sync_upload` 已按文件顺序执行，每个文件也使用 `parallel_upload: false`、顺序分片和相邻签名 PUT 至少 350 ms 的节拍。但是多个独立上传 Tool 调用仍可同时执行，各自的签名 PUT 节拍互不共享。官方文档没有公布签名 PUT 的独立 QPS，因此本设计同时封住该预防性并发缺口。

## 获批行为

- `skills/pan-sync-upload/SKILL.md` 要求多文件下载每次只调用一个 `pan_sync_download`，等待该调用结束后才调用下一个。
- `ReadOrchestrator` 共享一个容量为一的可取消 FIFO 下载门禁。
- 下载调用必须在获取 Token、资源盘上下文、文件元数据或下载地址之前取得门禁。
- 门禁覆盖远端元数据解析、大文件确认、工作区目标创建、取下载地址、内容流写入、字节数校验、文件关闭、失败清理和稳定错误映射。
- 调用成功、确认返回、失败或取消后，在 `finally` 中释放门禁，使下一调用开始。
- 排队期间不访问阿里云、不创建本地目录或文件。
- 保留全局 OpenAPI 350 ms 节拍、端点窗口、20 MiB 顺序分片上传以及无自动重试策略。

## 上传串行行为

- Skill 在一次用户请求涉及多个文件时，优先把全部已验证的工作区相对路径合并到一个 `pan_sync_upload.paths` 数组，不得并行发起多个上传 Tool 调用。
- `UploadOrchestrator` 共享一个容量为一的可取消 FIFO 上传门禁；不同 `pan_sync_upload` 调用必须逐个执行。
- 上传门禁在获取 Token、确保远端目录或启动任何文件上传前取得，并覆盖该 Tool 调用中的全部文件、全部分片和完成接口。
- 单次 Tool 调用内部继续按输入顺序逐个文件上传；单文件继续使用 `parallel_upload: false`、20 MiB 基准分片、顺序 PUT 和相邻 PUT 至少 350 ms。
- 等待门禁期间不访问阿里云、不打开工作区文件、不创建远端目录。
- 上传和下载使用两个独立的单通道门禁；一个上传与一个下载可以同时存在，但各自类别内部禁止并发。所有 OpenAPI 仍共享全局 350 ms 节拍。

## 错误与取消

- 排队等待期间取消时，该调用从 FIFO 队列移除并返回现有稳定下载错误，不影响下一等待者。
- 上传排队期间取消时不访问远端或打开本地文件，并返回现有稳定上传错误；门禁必须在成功、部分失败、全局失败或取消后释放。
- 已取得门禁后的失败继续折叠为既有稳定错误码，不暴露 Token、签名 URL、网盘 ID、文件名、绝对路径或原始响应。
- 大文件未确认时返回 `DOWNLOAD_CONFIRMATION_REQUIRED` 后立即释放门禁；用户确认后的新调用重新排队。

## TDD 与验证

1. 先修改并发测试，五个同时下载时只有第一个能进入任何远端 Provider 方法；旧实现应因前三个仍能并行而红灯。
2. 逐一完成模拟流后，仅允许下一个调用进入；最终五个均完成，最大远端下载生命周期并发为一。
3. 覆盖排队取消、元数据失败、大文件确认、内容流失败和门禁释放。
4. 更新 Skill 打包断言，要求明确写出一次一个、等待完成后继续，且禁止并行批次。
5. 增加上传并发测试：多个同时上传调用中只有第一个能取得 Token 或访问 Provider；完成、失败或取消后按 FIFO 只放行下一个。
6. 更新 Skill 打包断言，要求多文件优先合并到一个 `paths` 数组，并禁止并行上传 Tool 调用。
7. 运行聚焦测试与完整 `npm run verify`，构建并安装精确 tarball。
8. 在线 Gateway、插件注册和三项 Tool 门禁通过后，只执行一次五文件串行下载真实验收：复用既有文件选择，不重新列目录、不重试、不上传、不删除远端数据。上传串行只用确定性本地测试验证，本轮不增加真实上传流量。

成功标准：五次下载 Tool 调用严格串行，五项均返回 `downloaded`，并且省略 `localDirectory` 时五个文件均落在 OpenClaw 工作区根目录；多个上传 Tool 调用在本地测试中严格 FIFO 串行，任何时刻最多一个上传生命周期访问远端。若真实下载仍有失败，立即停止真实请求，不改用循环重试或继续试探冷却时间。

## 非目标

- 不测量或宣称阿里云服务端并发占用的精确释放时长。
- 不增加固定批次冷却、自动重试、断点续传或跨 Gateway 分布式锁。
- 不修改上传分片大小、Token 获取、资源盘唯一路由或下载目标路径语义。
- 本轮不执行新的真实上传验收；已有顺序分片真实验收仍是独立证据。
- 不合并到 `main`、推送或创建 PR，除非用户另行授权。
