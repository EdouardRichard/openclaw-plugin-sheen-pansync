# 阿里云盘完整生命周期串行下载设计

**日期：** 2026-08-05

**状态：** 用户已批准方案，待书面复核

## 背景与判断

真实 OpenClaw 验收中，五个文件按 3+2 批次下载时，前三个稳定成功，后两个稳定返回 `DOWNLOAD_FAILED`。第二批虽然在前三个客户端流完成约 1.5 秒后才启动，但阿里云服务端可能仍在下载并发时间窗内保留前三个占用。

此前增加的 350 ms OpenAPI 请求节拍已确认安装生效，但未改变 3 成功、2 失败的结果。因此下一步不继续猜测服务端窗口长度，也不增加固定冷却或重试；直接把同一 Gateway 内的整个下载生命周期改为严格串行。

## 获批行为

- `skills/pan-sync-upload/SKILL.md` 要求多文件下载每次只调用一个 `pan_sync_download`，等待该调用结束后才调用下一个。
- `ReadOrchestrator` 共享一个容量为一的可取消 FIFO 下载门禁。
- 下载调用必须在获取 Token、资源盘上下文、文件元数据或下载地址之前取得门禁。
- 门禁覆盖远端元数据解析、大文件确认、工作区目标创建、取下载地址、内容流写入、字节数校验、文件关闭、失败清理和稳定错误映射。
- 调用成功、确认返回、失败或取消后，在 `finally` 中释放门禁，使下一调用开始。
- 排队期间不访问阿里云、不创建本地目录或文件。
- 保留全局 OpenAPI 350 ms 节拍、端点窗口、20 MiB 顺序分片上传以及无自动重试策略。

## 错误与取消

- 排队等待期间取消时，该调用从 FIFO 队列移除并返回现有稳定下载错误，不影响下一等待者。
- 已取得门禁后的失败继续折叠为既有稳定错误码，不暴露 Token、签名 URL、网盘 ID、文件名、绝对路径或原始响应。
- 大文件未确认时返回 `DOWNLOAD_CONFIRMATION_REQUIRED` 后立即释放门禁；用户确认后的新调用重新排队。

## TDD 与验证

1. 先修改并发测试，五个同时下载时只有第一个能进入任何远端 Provider 方法；旧实现应因前三个仍能并行而红灯。
2. 逐一完成模拟流后，仅允许下一个调用进入；最终五个均完成，最大远端下载生命周期并发为一。
3. 覆盖排队取消、元数据失败、大文件确认、内容流失败和门禁释放。
4. 更新 Skill 打包断言，要求明确写出一次一个、等待完成后继续，且禁止并行批次。
5. 运行聚焦测试与完整 `npm run verify`，构建并安装精确 tarball。
6. 在线 Gateway、插件注册和三项 Tool 门禁通过后，只执行一次五文件串行真实验收：复用既有文件选择，不重新列目录、不重试、不上传、不删除远端数据。

成功标准：五次 Tool 调用严格串行，五项均返回 `downloaded`，并且省略 `localDirectory` 时五个文件均落在 OpenClaw 工作区根目录。若仍有失败，立即停止真实请求，不改用循环重试或继续试探冷却时间。

## 非目标

- 不测量或宣称阿里云服务端并发占用的精确释放时长。
- 不增加固定批次冷却、自动重试、断点续传或跨 Gateway 分布式锁。
- 不修改上传分片、Token 获取、资源盘唯一路由或下载目标路径语义。
- 不合并到 `main`、推送或创建 PR，除非用户另行授权。
